# 右侧边栏 IA 重构（2.2.0 第一批）

状态：已实现（2.2.0 第一批）；Gitee / 自动隔离 worktree 仍按版本线后续推进。

## 1. 目标

把右侧边栏从「4 页签 + 动态大杂烩」重构成按用途分页的管理台：

- 现有「动态」改为「更多」：收纳杂项；右侧被压缩时，被折叠的页签以列表形式存放在这里。
- 新增「地图」：任务地图票子的综合列表（本地票子 + 远端仓库映射），接替动态页的地图 / 票子。
- 新增「PR」：远端 PR 审批、评论与状态列表。
- 新增「分支」：本地与远端分支管理，决定删除 / 清理，避免盲占本地存储。
- 新增「问题」：单独 issue 处理列表，不与地图混在一起（从原有票子里拆出来）。
- 仓库守候的相关设置收进右侧边栏「设置」，卫星环继续做状态入口。

## 2. 页签 IA

宽屏（侧栏容器 ≥ 620px）：

```
会话 · 任务 · 交接 · 地图 · PR · 分支 · 问题 · 邮箱 · 更多
```

窄屏（< 620px）：

```
会话 · 任务 · 交接 · 邮箱 · 更多
```

- 地图 / PR / 分支 / 问题 在窄屏折叠进「更多」，以**列表入口**呈现；点进去是整页，带「返回更多」。邮箱不折叠，窄屏也保留独立页签。
- 折叠按侧栏容器宽度（`ResizeObserver` 量 root 宽度后加 `dshaSv_wide` / `dshaSv_narrow`，断点 620px；不使用 CSS 容器查询），不是窗口宽度；用户拖动侧栏宽度即时切换。
- 「更多」在宽屏也保留，收纳：GitHub 账号/登录、仓库探测与开关、同步队列；窄屏再加折叠页入口。邮箱已拆成独立页签。
- 顶栏不变：工作区、GitHub 账号胶囊、刷新、设置齿轮。

## 3. 各页签内容

### 3.1 会话 / 任务 / 交接

保持现状，不重做。只做两件事：页签图标/文案对齐；切页时沿用现有滚动复位与记忆。

### 3.2 地图（新）

- 内容：现有任务地图（`taskBoard.map` 父子票）+ 本地票子列表（`sync.links` 最近 8 条）+ 远端状态胶囊。
- 动作：拆分子任务（沿用 `task-split`）、打开远端 issue/PR 链接。
- 远端部分本批不新增拉取：显示同步队列里已有的远端状态（open/closed/unknown）；真正的远端仓库地图拉取放后续阶段。
- 布局：与 PR / 问题页一致，不套外层卡片；标题栏 + 票子卡列表，票子区标题栏带显示条数。
- 空态：`看板还没有任务；先建任务再拆分子任务。`

### 3.3 PR（新）

- 数据：只读视图 `pr-list`（`state=open|closed` 两个缓存键，5 分钟；刷新强制、写后失效）与 `pr-detail`（点「详情」按需拉正文、评审、评论与文件改动，悬停「详情」预取）。列表带 `additions` / `deletions` / `changedFiles`，详情带 `files`（路径、增删行、changeType）。
- 展示：编号 + 标题（可点开 GitHub）+ 作者 + 状态胶囊（草稿 / 待审 / 已请求修改 / 已批准 / 已合并）+ 更新时间 + 评论数 + `+A −D` / 文件数；关联任务号（若有）。打开 / 已关闭切换；打开列表另有「全部 / 待审 / 需处理 / 已批准 / 草稿」筛选与计数。冲突胶囊先不做：`gh pr list` 不保证给出可靠的 mergeable，要逐条读详情，留到后续。
- 动作：标题 / 编号开 GitHub；刷新（保留当前打开 / 已关闭状态）；「处理」里批准、请求修改、评论、关闭 / 重开；「关联任务」输入任务号（沿用 `task-pr`，用户点击；成功后刷新看板）；行内「AI 审核」拉起只读审核会话（见下）。
- **审批 / 评论 / 关闭 / 重开只由用户点击**：批准 / 关闭 / 重开二次确认，评论 / 请求修改点按钮即带正文发出（请求修改必须有说明）。写前校验 GitHub 身份与账号锁定，写后清列表 / 详情缓存、刷新列表并记一条审计。
- 详情就地展开 PR 正文、文件改动（最多列 30 个，带新增 / 修改 / 删除类型）、评审与评论（作者链接到 GitHub）；长正文折四行可展开；写动作成功后详情重新拉取；标题栏给「在 GitHub 打开 PR」。
- **AI 审核（用户点击）**：在本工作区新建一个只读审核工作会话（工作区工作会话模型），首条消息带仓库 / PR 号 / URL，要求它用 `gh pr view` + `gh pr diff` 审「最新改动」并按必须修 / 建议修 / 可忽略汇报；会话里明确禁止改文件、commit / push、`gh pr review/comment/merge/close`。创建后直接打开新会话；模型工具没有这个入口。
- 模型仍然没有 GitHub 写入口：这些动作只走用户页面路由，不注册成模型工具；错误用文字显示，不静默重试。
- 合并（merge）不在本批；先做审批、评论与状态。
- 空态：打开 / 已关闭 / 筛选无匹配分别给文案；仓库或 GitHub 错误时只显示原因，不叠「没有 PR」。

### 3.4 分支（新）

- 范围：**所有已登记工作区**；每个工作区显示自己的仓库、本地分支与远端分支；没有仓库的工作区给空态。
- 数据：
  - 本地分支：`git -C <workspace> branch --format`（当前、上游、ahead/behind、最后提交时间、是否已合并）；
  - 远端分支：`gh api repos/<owner/name>/branches`（名称 + 最后提交 SHA/日期），`git branch -r` 兜底。
- 展示：按工作区分组，组内「本地 / 远端」；当前分支置顶；显示「已合并 / 未合并」「领先/落后」「最后提交 x 天前」。
- 动作（只由用户点击，单条二次确认）：
  - 本地删除：`git branch -d`；未合并时默认拒绝，需勾选「强制删除未合并分支」才走 `-D`；
  - 远端删除：`git push origin --delete <branch>`；确认框要求输入分支名，且拒绝默认分支（main/master/仓库默认分支）与当前分支；
  - 刷新 + 拉取（`git fetch --prune`，只更新远端引用，不动本地分支）。
- 安全：2.2.0 不自动清理、不批量删除，每次只删一条；确认框显示工作区、分支名、是否未合并、上游、是否默认分支；写后刷新。未发版的 2.3.0 追加「遗留分支清理」子页，是本页唯一允许多选的批量动作（仍需一次确认、服务端逐条复核），见 `docs/branch-cleanup.md`。
- 空态：`还没有登记工作区，或工作区没有仓库。`

### 3.5 问题（新）

- 数据：新增只读视图 `issue-list`，`gh issue list --repo <owner/name> --state open --json number,title,author,labels,assignees,updatedAt,comments,url`（最多 50 条，缓存 60s）。
- 展示：编号 + 标题 + 作者 + 标签胶囊 + 指派 + 更新时间；与本地任务关联的显示任务号（复用同步映射）。
- 动作：打开 GitHub；「关联任务」；刷新。与地图分开，不再把 issue 混进地图票子列表。
- 空态：`当前仓库没有打开的 issue。`

### 3.6 更多（原动态）

- 常驻区块：同步队列摘要、仓库探测摘要（只读，开关与登录在「设置」）；邮箱在独立「邮箱」页签。
- 窄屏才显示「快捷入口」：地图 / PR / 分支 / 问题 / 设置（带计数），点条目切到对应页 / 打开设置；宽屏已有这些页签，**不要重复列**。入口 section 必须挂 `dshaSv_foldOnly`，隐藏规则用 `.dshaSv .dshaSv_foldOnly` 双类名（单类名会被 `.dshaSv_sec{display:grid}` 覆盖，2026-11-08 因此复发过；详见维护指南 §3）。
- 移除：地图 / 票子 / PR / 守候卡 / 邮箱（分别迁到地图、PR、设置、邮箱页）；GitHub 账号与登录只在「设置」，不在「更多」重复。

### 3.7 仓库守候

- 卫星环（上一稿）：输入框左侧状态环 + 悬浮快捷面板，继续做状态入口。
- 设置：右侧边栏「设置」新增「仓库守候」区块：
  - 总览：每条守候的状态、下次轮询、上次唤醒、最近批次、错误、补报状态；
  - 判定：为什么叫醒/没叫醒（过滤原因、延后原因、退避、每小时用量）；
  - 触发：立即检查、暂停/恢复、观察模式、本机 ack、用户态 GitHub ack 标签；
  - 设置：间隔、批量、每小时上限、活跃时段、ack 标签、补报小时数、过滤项；登记/停止。
- 「动态」里的守候卡删除；卫星环悬浮面板的「打开完整面板」改为打开设置并定位到「仓库守候」。

## 4. 数据与接口

| 视图/动作 | 说明 |
| --- | --- |
| `view=pr-list` | 只读，`session=<id>` 取当前工作区仓库；`state=open|closed`；带 `additions/deletions/changedFiles`；返回 `{repo, state, items, error?}`；5 分钟缓存（并发合并、刷新强制、写后失效） |
| `view=pr-detail` | 只读，按 PR 号取正文、评审、评论与 `files`（+`additions/deletions/changedFiles`）；点「详情」按需拉，悬停预取；5 分钟缓存 |
| `action=task-pr` | 用户点击：PR 页把 PR 关联到本地任务（沿用任务页动作，可 clear 解除） |
| `view=issue-list` | 只读，同上；返回 `{repo, items, error?}` |
| `view=branch-list` | 只读，遍历所有已登记工作区，返回本地/远端分支；本地用 git，远端用 gh；60s 缓存 |
| `action=branch-delete` | 用户点击删除分支：本地 `git branch -d/-D`、远端 `git push origin --delete`；二次确认 + 远端要求输入分支名 |
| `action=branch-fetch` | 用户点击 `git fetch --prune`（只更新远端引用，不删本地分支） |
| `view=branch-cleanup` | **未发版**：只读，列工作树占用且不是主 checkout 的本地分支，带路径 / 干净 / 声明 / 已合并 / 可清理原因；只返回有遗留的工作区 |
| `action=branch-cleanup` | **未发版**：用户点击，批量移除工作树并删分支；`items=[{workspaceId,name}]` + `confirm:true`，逐条重新校验，跳过项回传原因 |
| `action=pr-review` | 用户点击：approve / request-changes（可带说明），身份校验 + 确认 + 审计 |
| `action=pr-comment` | 用户点击：PR 评论，带正文校验 |
| `action=pr-state` | 用户点击：关闭 / 重开 PR，二次确认 |
| `repo-watch-*` | 已存在；设置区块复用；新增 `backlogHours` |
| `view=watch-status` | 卫星环紧凑状态（上一稿） |

- 所有 gh 查询走 `github.requireIdentity()`，账号锁定/未登录时返回可读错误，不缓存错误结果。
- 仓库来源：当前工作区注册仓库（`gh` 的 `--repo`）；没有仓库时显示空态，不给假数据。
- 缓存按工作区 + 视图 60 秒；刷新按钮强制绕过缓存。

## 5. 安全边界

- 模型没有 GitHub 写入口；PR 批准/评论/关闭只走用户页面路由，不注册模型工具。
- 远端分支删除与 PR 状态修改都要身份校验、单条确认、写后刷新与审计；失败只显示文字，不自动重试。
- 分支删除禁止默认分支与当前分支；远端删除要求输入分支名。
- 任何清理动作不自动执行；唯一的多选批量动作是「遗留分支清理」，一次确认后仍逐条重新校验（`.agents/worktrees` 下、干净、无 `.ACTIVE-SESSION`），未合并要额外勾选；不做定时 / 自动清理。`git fetch --prune` 只动远端引用，不动本地分支。
- 工作区路径必须来自已登记工作区，不接受任意路径。

## 6. 响应式折叠

- 侧栏根节点用 `ResizeObserver` 测宽度；`< 620px` 进入紧凑模式。
- 紧凑模式 DOM：只渲染 会话 / 任务 / 交接 / 更多 四个按钮；地图/PR/分支/问题作为「更多」里的入口列表。
- 从「更多」点入折叠页时，渲染该页整页 + 顶部返回；切回其他主标签自动退出。
- 宽屏恢复八页签；当前页不在可见页签时回落到「更多」。
- 页签按钮沿用现有胶囊/图标风格，计数 badge 保留。

## 7. 实施顺序

1. **壳层**（已提交）：页签键位与渲染（activity→more）、响应式折叠、更多页整合、旧区块迁移；纯 UI，不动后端。
2. **地图/问题拆分**：地图页只留地图 + 本地票子；问题页接 `issue-list` 只读视图。
3. **PR 页**：`pr-list` + 列表 + 关联任务；再做审批 / 评论 / 关闭重开（用户路由 + 确认 + 审计）。
4. **分支页**：`branch-list`（全工作区）+ 本地/远端删除 + fetch（危险动作 + 测试）。
5. **守候**：卫星环 + 设置区块（上一稿），补报 `backlogHours`；移除动态页守候卡。
6. 文案 zh/en、测试、文档、真机验收（待用户 `/relay reload` 后验证）。

每步单独提交，保持串行测试全绿；先做 1–2 给用户看效果，再继续 3–5。

## 8. 测试计划

- 侧栏壳层：8 页签键位；宽/窄两套渲染；紧凑模式折叠入口；更多页区块齐全；设置区块可达。
- `pr-list` / `issue-list` / `branch-list`：纯函数解析 gh/git 输出；未登录/无仓库/超时/错误；缓存与强制刷新。
- `branch-delete`：只接受已登记工作区；未合并默认拒绝；强制删除需显式标记；shell 参数不拼接用户输入。
- 回退：旧服务端没有新视图时不崩，显示「加载失败/不可用」。
- 回归：现有 362 项 + 新增项全过（串行）。

## 9. 已确认（2026-11-08）

1. 「更多」= 杂项 + 窄屏折叠入口；GitHub 账号只在设置，不重复。
2. PR 审批 / 评论在侧栏内做（只由用户点击，新增写路由与审计）；模型无写入口。
3. 分支覆盖所有已登记工作区；本地与远端都可删（逐条确认，远端要输入分支名）。
4. 地图的「远端仓库地图」本批先用同步映射，不新增远端树拉取。

## 10. 验收

1. 宽屏九页签、窄屏五个页签 + 更多里的折叠入口；拖动宽度即时切换。
2. 地图、问题、PR、分支四个页签各自有真实数据/空态/错误态，不互相混。
3. 分支删除需二次确认，未合并默认拒绝，默认分支/当前分支不可删，远端删除需输入分支名；没有自动清理。
4. 设置里能管理仓库守候（含补报），动态页不再出现守候卡。
5. 串行测试全过；zh/en 文案同步；旧版服务端降级不崩。
