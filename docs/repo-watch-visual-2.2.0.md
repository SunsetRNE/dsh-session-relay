# 仓库守候完整可视化（2.2.0 第一批）

状态：已实现（2.2.0）。

## 1. 背景与定义

2.1.0 已有仓库守候核心：只读轮询 GitHub、过滤、空闲唤醒、观察模式、本机 ack、侧栏「动态」卡片。

2.2.0 第一批做「完整可视化 + 存量补报」，对齐用户指定的参考插件 `dsh-session-superagent`：

- 参考插件的 `conversation.composer.dock`（输入框左侧）挂 `OrbitBadge`：一眼看到本会话所有守候的运行 / 暂停 / 异常，点开是悬浮面板。
- 中间栏面板四个页签：总览 / 判定 / 触发 / 设置。
- 注意：这里的「卫星环」是**会话级守候的状态入口**，不是「工作会话围绕主会话」的多会话拓扑；后者不在本批范围。

用户已确认：按参考插件定义 + 存量补报推进；先设计稿，再实现。

## 2. 范围

本批（按顺序）：

1. 卫星环：输入框左侧状态徽标 + 悬浮快捷面板。
2. 完整面板：收进右侧边栏「设置」的「仓库守候」区块，含总览 / 判定 / 触发 / 设置四个子页签（不新增顶级页签）。
3. 存量补报：登记守候时可选「补报最近 N 小时」，只补一次，让登记前已经在等的条目也能被叫醒。
4. 文案（zh/en）、测试、`docs/repo-watch.md` 同步。

不在本批：Gitee、自动隔离 worktree（2.2.0 后续阶段）；多会话拓扑图。

## 3. 交互总览

```
输入框左侧 [◉ 卫星环] ──点击──▶ 悬浮面板（本会话守候列表 + 快捷动作）
        │                             │
        └──「打开完整面板」──────────▶ 右侧边栏 设置 → 仓库守候
                                          总览 / 判定 / 触发 / 设置
```

- 两个入口看同一份状态：卫星环只显示**本会话**的守候；设置区块显示**本工作区**的守候（与服务端 `repoWatches` 视图一致）。
- 动作统一走后端用户路由 `repo-watch-*`；模型工具 `peer_repo_watch` 行为不变（新增 `backlogHours` 参数）。

## 4. 卫星环

### 4.1 位置与显示

- 插槽：`conversation.composer.dock`，注册 id `session-relay-watch`，order `-10`（最左）。
- 当前会话没有守候时不渲染（避免常驻噪音）；有一个以上守候时显示。
- 形态：直径 24px 的轨道环 + 中心状态点 + 右下角数量胶囊；只含矢量/CSS，不用图片。
- 状态优先级：`error`（红）> `rate`/`activeHours`/`busy` 延后（黄）> `observe`（空心蓝）> `running`（绿）> 暂停（灰，仅当全部暂停）。
- 数量：本会话启用的守候数；`aria-label="仓库守候：N 个，状态…"`。

### 4.2 悬浮面板

- 点击卫星环展开，锚定在输入框上方；宽 320px，最大高 60vh，内容滚动。
- 头：`仓库守候` + 本会话数量 + 关闭按钮。
- 每条守候一行：状态点 + `owner/name` + 状态胶囊（守候中/观察中/已暂停/错误）；第二行 `下次 12s · 上次唤醒 3 分钟前` / `上次错误：…` / `过滤中：最近原因`。
- 快捷动作：`检查`（repo-watch-check）、`暂停/恢复`（repo-watch-toggle）、`ack`（仅当有 `lastBatch`，本机 ack）。
- 空态：`本会话还没有守候。在「设置 → 仓库守候」登记一个仓库。`
- 错误态：轮询失败时红点 + 一行原因（文字，不用 toast）。
- 关闭：Escape / 点外部 / 再点卫星环；打开时焦点进面板，关闭后回卫星环。
- 动效：只做一次性状态切换淡入；`prefers-reduced-motion` 时关闭。
- 底部按钮：`打开完整面板` → 打开右侧边栏「设置」并定位到「仓库守候」区块（见 5.1）。

### 4.3 数据与刷新

- 新用户路由视图 `watch-status`：按当前会话过滤，只返回紧凑字段：
  `id, repo, enabled, observe, lastPoll, lastWake, nextAt, deferReason, lastError, lastBatch(最多3), wakeCountLastHour, backlogPending`。
- 打开时拉一次；面板开着时每 20s 拉一次；动作成功后立即刷新；`visibilitychange` 回到前台刷新。
- 静默失败：保留上次数据，环上加黄点提示「刷新失败」，不弹错误。

## 5. 完整面板

### 5.1 入口

- 右侧边栏「设置」（顶栏齿轮）新增「仓库守候」区块；不新增顶级页签（页签 IA 见 `docs/sidebar-ia-2.2.0.md`）。
- 卫星环悬浮面板底部 `打开完整面板` → `setSettingsOpen(true)` 并滚动/展开到「仓库守候」区块；派发 `dsh-session-relay:open-watch` CustomEvent 给已打开的侧栏，未打开时由侧栏事件监听兜底。
- 「更多」页不再放守候卡（原「动态」守候卡删除）。

### 5.2 总览

- 顶部统计胶囊：守候数 / 运行中 / 观察 / 暂停 / 错误 / 本小时已唤醒。
- 每条守候一张卡：仓库名（等宽）+ 状态胶囊 + 目标摘要；`间隔 120s · 下次 1m · 上次唤醒 …`；`补报待执行` 或 `已补报 N 条`；最近一批条目（最多 3 条，带 #号、标题省略、点击去 GitHub）；错误一行。
- 动作：检查 / 暂停恢复 / ack / 打开 GitHub。
- 空态：`还没有守候。到「触发」页登记一个仓库。`

### 5.3 判定（为什么叫醒 / 为什么没叫醒）

- 每条守候一个折叠组，展开显示：
  - 最近 5 条 `history`：唤醒 / 观察 / 轮询失败，带编号与时间；
  - 最近 4 条 `filteredLog`：`#42 已关闭 / 排除标签：wontfix / 不在标签白名单 …`；
  - 最近一次延后：`忙 / 活跃时段外 / 每小时上限 / 绑定会话不在`（文字 + 时间）；
  - `本小时已唤醒 N / 上限 M`；
  - 上次错误 + 连续失败次数（退避中）。
- 空态：`还没有判定记录。`

### 5.4 触发

- 每条守候：立即检查、暂停/恢复、观察模式开关、本机 ack（最近一批编号）、用户态「在 GitHub 打 ack 标签」（仅用户点击，模型没有写入入口）。
- 登记新守候表单：仓库（owner/name 或 URL）、目标、间隔、活跃时段、补报最近 N 小时、观察模式；高级过滤折叠（标签 / 排除标签 / 作者 / 仅指派 / 指派给 / 跳过关闭、草稿、机器人）。
- 校验沿用后端：间隔 60–3600、批量 1–10、每小时 1–30、标签 ≤50、仓库写法；错误用文字贴在字段下。

### 5.5 设置

- 每条守候一个编辑组（折叠）：间隔、批量、每小时上限、活跃时段、ack 标签、补报小时数、观察、过滤项；保存 → `repo-watch-update`；停止 → `repo-watch-stop`（二次确认）。
- 底部说明：GitHub 只读；Gitee / 自动隔离 worktree 在 2.2.0 后续阶段。

## 6. 存量补报

### 6.1 参数

- 新参数 `backlogHours`：整数 0–720，默认 `0`（关闭）。`start` 与 `update` 都接受；`update` 传 `>0` 会重新武装一次补报。
- 语义：登记后的**第一次成功轮询**里，把「最近 N 小时内更新过、且不在 `seen` 水位里」的条目当成 fresh；补报只做一次。
- 现有 `cursor` 仍是登记时刻；补报用 `backlog.setAt - N 小时` 作为水位下限，不改正常水位。

### 6.2 行为

- 补报期间照常走过滤（关闭/草稿/机器人/标签/作者/指派/ack 标签）与批量排序；`batchLimit` 限制单次条数，其余留到下一轮（仍算 fresh）。
- 观察模式下补报只写 `history(reason=observe)`，不发消息。
- 唤醒消息首行加 `首次补报：登记前最近 N 小时的动态`，让模型知道这是存量。
- 下列情况**保留** `backlog.pending`，下次空闲再补：会话忙、活跃时段外、每小时上限、会话不存在、轮询失败。
- 下列情况**消耗**（`pending=false`，记 `doneAt`）：成功完成一次轮询（唤醒、观察、或没有 fresh 条目）。
- 面板与卫星环显示 `补报待执行 / 已补报` 状态。

### 6.3 为什么需要

用户真实场景：隔壁仓库 5 个 PR 已改完等复审；2.1.0 只报登记后的新动态，这 5 个永远不会被叫醒。补报让「登记那一刻已经在等的事」也能被列出来一次，不改变之后的增量语义。

## 9. 风险与取舍

- `conversation.composer.dock` 的 `sessionId` 注入依赖宿主 slot 约定；实现时先用 `inject: (sessionId) => ({ sessionId })`，若宿主不传则退回隐藏（不报错）。
- 悬浮面板用 `position: fixed` 按环的位置计算；窗口 resize/滚动时重新定位，避免被输入框裁切。
- 补报会一次列出很多条目：用 `batchLimit` 分批，API 每轮仍只拉 50 条，避免刷屏。
- 设置页本身较长：仓库守候区块用折叠组收在设置页末尾，默认展开总览；四子页签在窄栏用胶囊横向滚动。
